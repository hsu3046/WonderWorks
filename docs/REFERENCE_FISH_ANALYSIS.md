# 深海鱼群 — 녹화 기반 재현 명세

**TL;DR:** 원본 UI와 사용자 녹화에서 6,144마리 군집, 청록색 수중 장면, 수면의 밝은 패턴, 빛기둥, 바닥·바위의 집광 무늬, 해초와 부유 입자를 확인했다. 사용자 명시사항인 마우스 휠 줌을 포함해 두 번째 독립 작품으로 재구현한다. WebGPU 기반 구현과 프로젝트 전용 패키지 설치를 사용자에게 승인받아 `projects/fish/`에 구현했다.

분석일: 2026-09-29

## 근거와 한계

- 원본: https://threejs-fish.vercel.app/
- 사용자 녹화: `Screenshot 2026-09-29 0.09.07.mov`, 52.225초, 2560 × 1168, 약 57.4fps의 녹화 파일. 이 수치는 앱의 실제 FPS가 아니다.
- 샘플 이미지: `references/fish/frames/`, 0–45초에서 5초 간격 10장.
- 고해상도 참조: `references/fish/closeup/`, 35초 프레임.
- 입력 종류 추가 확인: 사용자가 “마우스 스크롤로 줌인 줌 아웃 기능잇음”이라고 명시.
- 라이브 DOM에서 `深海鱼群 · WebGPU`, `6144 条鱼 · WebGPU 计算着色器`, 포인터 분산·클릭 충격파 안내와 접힌 화면 조절 패널을 확인했다.
- 원본 브라우저는 이후 캡처 및 탭 재선택에서 응답 제한을 넘겼다. 이후 반복 접속하지 않고 제공 녹화를 분석했다.
- 원본 소스·모델·셰이더는 확보하지 않았다. WebGPU 사용과 마릿수는 UI의 표기이며 실제 구현 경로를 검증한 결과가 아니다.
- 40초 부근에 나타나는 운영체제 제어센터는 작품 UI가 아니므로 재현 대상에서 제외한다.
- 샘플 시각은 seek 요청 시각 근처 프레임이다. 클릭 순간이나 휠 입력량을 정확히 측정한 것은 아니다.

## 시각 구성

| 층 | 관찰한 외형 | 재구현 제안 — 원본 구현 확인 아님 |
|---|---|---|
| 수중 배경 | 상부의 밝은 청록색에서 먼 곳의 짙은 청색으로 변화 | 거리 안개와 깊이별 색 흡수 |
| 수면 | 위를 볼 때 밝고 불규칙한 수면 무늬 | 움직이는 절차적 노이즈와 수면용 셰이더 |
| 빛기둥 | 위에서 아래로 비스듬히 퍼지는 부드러운 빛줄기 | 깊이감을 주는 여러 빛층 또는 볼륨 근사 |
| 해저 | 밝은 바닥 전체에 푸른색·연두색 집광 무늬 | 시간에 따라 변하는 caustics 패턴 |
| 바위 | 낮고 둥글며 면이 드러나는 회색·청록색 바위, 표면에도 빛무늬 | 직접 생성한 저다각형 지오메트리와 공통 집광 셰이더 |
| 해초 | 가늘고 길며 일부는 가까이 크게 보이는 풀잎, 무리지어 배치 | 인스턴싱과 정점 휘어짐 |
| 부유 입자 | 크기와 거리감이 다른 밝고 흐린 점 | 깊이와 크기를 분산한 입자 |
| 물고기 | 은회색 등, 밝은 배, 눈, 지느러미와 갈라진 꼬리 | 직접 만든 물고기 메시, 인스턴싱, 몸·꼬리의 정점 애니메이션 |
| 군집 | 조밀한 기둥·곡선·큰 빈 공간을 둘러싼 무리 등으로 지속 변화 | 응집·정렬·분리와 유영장, 외력에 반응하는 시뮬레이션 |

물고기를 단순 점이나 동일 방향의 스프라이트로 대체하면 근접 줌에서 원본과 차이가 크게 드러난다. 가까운 물고기의 몸체와 꼬리 형태를 먼저 확보해야 한다.

## 휠 줌 구현 기준 제안

- 가까이서 개별 물고기를 보고, 멀리서 전체 무리를 볼 수 있도록 한다.
- 휠 목표값으로 부드럽게 이동하고 카메라 거리에 상·하한을 둔다.
- 초기 제안은 카메라를 앞뒤로 이동시키는 방식이다. 원본이 FOV 변경을 쓰는지 카메라 이동을 쓰는지는 미확정이다.
- 물고기와 지형의 깊이감, 근접 물체의 잘림, 해저 관통을 확인하면서 범위를 조정한다.
- 휠로 화면 자체가 스크롤되지 않게 처리하고 트랙패드의 연속 입력도 확인한다.
- 줌 상태가 달라져도 포인터와 군집의 반응 위치가 어긋나지 않도록 화면 좌표를 3D 상호작용 좌표로 변환한다.

## UI

- 왼쪽 아래: 넓은 자간의 `深 海 鱼 群`, 포인터/터치·충격파 안내, 마릿수와 렌더링 방식.

- 녹화 샘플에서 패널은 접혀 있다. 내부의 실제 조절 항목과 기본값은 확인하지 못했다. 새로 제공하는 조절 항목은 원본 확인값으로 표시하지 않는다.

## 구현 선택지

| 방식 | 장점 | 고려할 점 |
|---|---|---|
| 1. Three.js WebGPU 기반 독립 작품 — 추천 | 원본이 표방하는 계산 방식과 6,144마리 목표를 유지하고 GPU에서 군집 갱신 가능 | 대상 장치의 WebGPU 실행·성능 검증 필요 |
| 2. Three.js WebGL2 기반 재현 | WebGPU가 없는 환경도 우선 고려 가능 | 군집 계산 경로를 다르게 구성해야 하며 원본 기술 표기는 그대로 사용할 수 없음 |

두 방식 모두 영상의 외형·상호작용을 새 코드로 재현하는 것이다. 원본 내부 알고리즘이나 동일한 궤적을 복구한다는 뜻은 아니다.

기술 검토 근거:

- [Three.js WebGPURenderer](https://threejs.org/docs/pages/WebGPURenderer.html)
- [StorageBufferNode: 계산 버퍼와 인스턴스 속성 연동](https://threejs.org/docs/pages/StorageBufferNode.html)
- [Renderer: compute 실행과 자원 해제](https://threejs.org/docs/pages/Renderer.html)

WebGPURenderer 자체에는 WebGL2 fallback이 있지만, 이번에 작성할 계산 셰이더와 전체 효과의 호환성이 자동으로 보장되는 것은 아니다. 실제 작성할 경로를 기준으로 검증해야 한다.

## 구현·검증 순서

1. `projects/fish/`를 독립 작품으로 구성한다. 기존 `projects/shabon/`은 기준본을 유지한다.
2. 물고기의 근접 형상, 해저·수면·바위·해초와 수중 조명을 만든다.
3. 6,144마리 군집 갱신과 몸·꼬리 애니메이션을 연결한다. 모든 개체 쌍을 무조건 전수 비교하는 방식은 피하고 성능을 측정한다.
4. 포인터 분산, 클릭 충격파, 휠 줌을 연결한다.
5. 같은 화면 비율의 원본 프레임과 나란히 비교해 색감, 물고기 밀도, 빛무늬, 원근감을 조정한다.
6. 실제 GPU에서 기본·근접·원거리 장면, 연속 휠 입력, 창 크기 변경, 탭 숨김·복귀와 메뉴 조작을 검증한다.

새 작품의 소스·절차적 에셋은 이 작업 공간의 기본 GNU GPL v3 정책을 따른다. 원본 사이트의 에셋을 확보하거나 새 작품에 포함한 상태는 아니다.

## 2026-09-29 — 움직임 재분석과 개선

사용자 피드백: 빛·물고기 움직임·대담한 카메라 워크 부족. 원본 녹화를 0~36초, 2초 간격 19장으로 다시 추출했다(`references/fish/motion-study/`).

| 시각 | 관찰 | 구현에 반영한 판단 |
|---|---|---|
| 0~6초 | 큰 세로 무리에서 수면이 보이는 넓은 시점으로 이동. 전경 해초 위치와 원근 변화 | 카메라 위치 이동과 위쪽 주시점 전환을 함께 사용 |
| 10~20초 | 군집 회전 방향·밀도가 변하고 가운데 큰 빈 공간이 생김 | 고정 원통의 얇은 표면을 유지하는 힘 대신 3D 회전축·입체 분포·수축/분리를 사용 |
| 24~32초 | 물고기가 화면 가장자리 가까이 통과하고 멀리 있는 무리와 크기 차이가 크게 나타남 | 군집 내부를 지나는 경로를 포함하고 근거리/원거리 parallax를 확보 |
| 전 구간 | 밝은 수면 아래 비스듬한 빛, 물고기의 반짝임, 먼 쪽의 산란 | 평면 빛띠를 제거하고 깊이 기반 광선 적분과 HDR Bloom 적용 |

원본 카메라가 자동 경로인지 녹화자의 수동 입력인지는 확인하지 못했다. 재현본의 기본 자동 경로 및 C 토글은 사용자가 요청한 대담한 카메라 워크를 구현하기 위한 새 설계다. 원본 알고리즘을 확보했다는 뜻이 아니다.
