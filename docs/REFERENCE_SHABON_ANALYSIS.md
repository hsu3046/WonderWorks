## 5. 모바일과 성능

- WebGL2 존재를 검사하고 지원되지 않으면 로딩 영역에 안내 문구를 표시한다.
- 터치 장치이며 화면의 짧은 변이 900 미만이면 LITE 모드를 선택한다. URL의 `lite` 플래그로도 선택할 수 있다.
- DPR 적용 상한은 1.25다. 초기 픽셀 예산은 LITE 약 90만, 일반 약 210만이다.
- 프레임 간격에 따라 렌더 해상도를 조정한다. 이는 성능 대응 코드의 존재를 뜻하며 60 FPS 실측 결과를 뜻하지 않는다.
- LITE에서는 화면 공간 차폐를 생략하고 근거리 그림자 갱신 빈도를 낮춘다.
- 세로 화면은 시야각 64도, 가로 화면은 52도다.
- 사운드는 숨긴 탭에서 suspend된다. 렌더 루프에는 `document.hidden`을 이유로 직접 중단하는 조건이 없으며 브라우저의 프레임 스케줄링에 영향을 받는다.
- 장면 전체를 해제하는 dispose/unmount 진입점은 확인되지 않았다. 갤러리 내부에서 작품을 여러 번 열고 닫는 구조로 바꾸면 수명주기 처리가 필요하다.
- `prefers-reduced-motion` 대응은 로딩 아이콘에만 확인된다. 본편의 자동 비행과 카메라 이동은 별도 검토 대상이다.

근거: `main.js:81–97,366,427–477,559,578,613–624`, `index.html:64`.

## 6. 빠진 부분과 재현 조건

### 일반 감상과 영상 출력의 차이

일반 감상 코드에는 앱 서버 API 호출이 필요하지 않다. 모듈과 에셋을 HTTP로 제공하고 외부 라이브러리·글꼴을 불러오는 구성이 전제되어 있다. 정적 호스팅으로 실행 가능한 구조로 판단되지만 실제 부팅은 아직 검증하지 않았다.

반면 `capture` 모드는 다음 서버 API를 호출한다.

- `/api/video/start`, `/api/video/frame`, `/api/video/end`
- `/api/still`
- `/api/log`

이 API의 구현과 ffmpeg 연동 서버는 ZIP에 없다. 따라서 ZIP만으로 영상 내보내기가 완결되지는 않는다. 관련 클라이언트는 `main.js:640–711`에 있다.

### 동일 장면 비교

시작 위치, 바람과 비행 경로에 난수가 들어간다. 재현 검증에서는 viewport, DPR, LITE 여부, 카메라, 시작 지점, 시간과 seed를 맞춰야 한다. seed 고정 코드는 `capture` 모드에 있으며 일반 감상 모드에서 seed 쿼리만 지정하는 것으로는 고정되지 않는다. capture 실행 시 누락된 서버 호출도 함께 고려해야 한다.

완전 동일한 화면 여부는 제공 ZIP을 기준으로 고정 조건에서 렌더링해 확인해야 한다. 현재 자료만으로 라이브 Artifact와 ZIP이 동일 버전인지, GPU·브라우저 간 픽셀 결과가 동일한지는 확정할 수 없다.

### 공개용 메타데이터

ZIP에서 작성자 표시와 LICENSE 파일을 확인하지 못했다. 원본 코드·이미지의 공개 조건은 이 자료만으로 확정할 수 없다. 갤러리의 원본 출처와 라이선스 표시는 별도 확인 항목으로 남긴다.

## 8. 구현 시 검증할 항목

1. 로딩 완료와 WebGL 셰이더 오류 여부, 나뭇잎 이미지 및 CDN·글꼴 로딩.
2. 고정 조건에서 8개 지점의 장면과 가로·세로 레이아웃 비교.
3. 탭/클릭 → 불기 → 추적 → 내부 시점 → 터짐 → 다음 지점의 전체 흐름.
4. 드래그 중 탭 오인 방지, 방향키, 모바일 pointercancel, 메뉴 열고 닫기.
5. 첫 입력 이후 소리 시작, 음소거, 메뉴의 볼륨 감소, 탭 복귀.
6. 데스크톱 및 실제 모바일 장치에서 부팅 시간, 프레임 시간, 해상도 변화, 메모리 측정.
7. 갤러리에 통합한 경우 작품 진입·이탈 반복 시 오디오와 GPU 리소스 해제.

현재 완료한 검증은 파일 목록·크기 집계, 상대 경로 import 대상 존재 검사, 주요 실행 경로의 정적 분석이다.
