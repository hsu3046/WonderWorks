# Golden Temple 실시간 최적화 결과

TL;DR: 실시간 경로를 분리해 캐시·거리별 디테일·수명주기·후처리·자동 해상도를 적용했다. 정지 화면과 유휴 상태의 낭비는 줄였지만, 카메라 이동 중에는 여전히 장면 전체의 정점·그림자·반사 비용이 크다. 30/60fps 달성으로 보고하지 않는다.

## 적용 내용

| 영역 | 변경 및 품질 조건 |
|---|---|
| 실행 정책 | dev + preview에서만 활성화. `?opt=0`으로 원본 정책 비교. still/render/final은 기존 전체 품질 경로 |
| 루프 | Pause 시 애니메이션 시간과 RAF 중단. 입력 시 한 프레임 요청. 숨김 시 취소, 복귀 시 시계 재설정. WebGL 손실 안내, 페이지 종료 시 GPU 자원/리스너 정리, bfcache 복귀 처리 |
| 해상도 | Balanced: 프레임 간격의 이동평균·최소45표본·4초 cooldown으로 65–100% 조절. High detail: 100% 고정. 화면 CSS 크기는 유지 |
| 반사·그림자 | 고정 구도에서 불필요한 재생성 방지. 애니메이션 최대20Hz 갱신, 반사 카메라 변경 시 즉시 갱신. 반사 MSAA4→2. 반사 전용 LOD 및 해상도 연동 |
| 하늘 | 정적 대기산란 LUT와 구름 밀도 필드 캐시. 구름 이동·태양 원반 유지, 밀도 캐시 범위 밖은 원래 계산. 추가 GPU 텍스처 메모리 약42MiB+LUT를 사용하는 시간/메모리 절충 |
| 형상 | 원본 속성을 공유하고 인덱스만 단순화. 화면 투영 오차와 hysteresis로 전환. 식생을 공간 셀로 나누고 변형 여유 bounds 적용. 가까운 잎은 유지, 먼 셀만80% 밀도 |
| 후처리 | Bloom/clarity가 꺼지면 관련 패스 생략. clarity만 켜지면 필요한4단계만 계산. AO/vol도 없고 spp1이면 누적 합성 생략. DOF/광선 작업 버퍼는 필요할 때 생성 |
| 시작 시간 | 식생 아틀라스와 alpha mip을 IndexedDB에 그대로 저장. LOD 인덱스는 소스 속성 SHA256 확인 후 재사용. 불상3종은 원본 생성기로 미리 계산한 무손실 바이너리 사용, 누락/손상 시 원래 생성기로 복귀 |
| 환경 조명 | 실시간 국소 환경 캡처1회, 실내128px. 원본2회/256px 대비 반사광 차이 가능. 최종 렌더는 유지 |
| CPU/소유권 | 물고기 방향벡터 재사용, 정지 카메라의 조명 순위 재계산 생략, 환경맵 렌더타깃 소유권 정리 |
| 계측 | `?bench=1&benchshot=0&bencht=5` 고정 구도, `&benchplay=1` 고정1/60초 경로 이동. 8프레임 준비 후32표본. 측정 후 자동 정지 |

큰 건축 메시 및 반복 건축물까지 세분화한 후보는 이동 시 draw call이 증가하여 제외했다. 모든 최적화 아이디어를 동시에 켜두는 것보다 실제 악화된 항목을 제외하는 정책을 택했다. 구조물 전체의 저밀도 재제작/텍스처 베이크, 정적·동적 그림자의 별도 합성은 구현하지 않았다. 기존 상세 모델을 보존하면서 적용 가능한 범위를 구현했다.

## 측정 조건과 결과

Apple M1 Pro / ANGLE Metal / IAB,1280×720,DPR1,전체 모듈,shot0,t5. 자동 해상도는 벤치마크에서 비활성화한다. 다른 앱/GPU 작업을 격리한 실험이 아니며 단일32표본 비교다. GPU timer는 RAF와 다른 지표이고 준비 구간의 비동기 샘플도 포함하므로 참고값이며, 절대 FPS로 변환하지 않는다.

| 이동 장면 중앙값 | 원본 정책 | 최종 후보 |
|---|---:|---:|
| 프레임 간격 |168.9ms|162.3ms|
| CPU 제출 시간 |7.6ms|9.2ms|
| GPU timer |255.1ms|315.0ms|
| draw calls/프레임 |804|1,024|
| 제출 삼각형/프레임 |65,727,531|62,595,507|
| 준비 시간 |17.95초|15.92초(캐시 사용)|

**이동 장면은 프레임 간격 약4% 감소에 그쳤고 CPU/GPU 지표 일부는 악화됐다. 큰 성능 개선이라고 해석할 수 없다.** 반사 카메라가 계속 이동하고 프레임 자체가50ms보다 길면 주기 제한으로 생략할 수 있는 작업이 적다. GPU 작업량의 주요 잔여 원인이다. 기본 Balanced의 해상도 조절 효과는 위 고정 해상도 수치에 포함하지 않았다.

최종 고정 구도는 제출 삼각형65,616,363→20,660,673(약69% 감소), 프레임 간격171.3→118.1ms(약31% 감소), CPU7.7→2.8ms, draw call802→338이었다. GPU timer261.6→230.3ms. 준비 시간15.67초(캐시 사용). 고정 구도와 이동 결과를 혼합하지 않는다. 실제 Pause는 반복 렌더 자체를 중단한다.

## 검증

- `npm test`:7개 통과. offline 분기, 갱신 게이트, 후처리 그래프, SDF 무손실/손상 거부, LOD 인덱스, 인스턴스 속성 대응, 해상도 bounds/cooldown.
- `npm run build`: 통과. 새 의존성 없음.
- 브라우저: Balanced가832×468까지 조절하고 High detail 클릭 시1280×720 복귀 확인.
- Pause 후 두 시점의 renderer frame4557/time17.90171199999105가 동일함을 확인. 7번 샷 전환과 재생/정지 정상.
- 실내7번 샷은 preview에서 과노출을 관찰했으며 `opt=0` 비교에서도 재현했다. 정상적인 실내 화질 검증 완료로 간주하지 않는다. 렌더 정책 변경과 별도로 원본 실내 preview 조명/노출 검토가 남는다.
- 최종 후보에서 새 브라우저 콘솔 오류 없음. 중간 공간분할 후보의 빈 `Object3D.add()` 오류는 해당 코드 제거로 해소.
- 전체70초 최종 영화 렌더와 모바일 실기기/장시간 발열/메모리 압박은 미검증.

증거 파일: `docs/validation/golden-temple/` (로컬 검증 산출물, Git 제외). baseline-moving.json, optimized-moving.json, baseline.png, optimized-final.png, original-interior.png, optimized-interior.png.

## 사용 및 재검증

1. 프로젝트에서 `npm run dev`, http://127.0.0.1:5173/ 실행.
2. Balanced에서 연못 주변을 드래그하고 숫자1–0으로 샷 전환. Pause 후 팬/회전하면 입력 시에만 그림이 갱신되는지 확인.
3. High detail과 Balanced의 선명도·반사·잎 그림자 차이를 비교. 원본 전체 정책은 `?opt=0`.
4. 재방문 캐시 사용 여부는 `[cache]`, `[lod] cacheHits` 로그에서 확인. 캐시가 없으면 첫 실행이 더 오래 걸릴 수 있다(초기 LOD 생성 후보 약36초 관찰).
5. SDF 생성식을 바꾸면 캐시 버전/키와 `npm run bake:sdf` 결과를 함께 갱신. 아틀라스 생성식을 바꾸면 atlas-cache REVISION 갱신.

원본 해시 목록은 원본 보존의 증거로 유지한다. 변경된 파일이 그 목록과 일치한다고 주장하지 않는다. 이번 작업은 로컬이며 푸시/배포하지 않았다.
